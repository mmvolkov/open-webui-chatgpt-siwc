# Open WebUI ChatGPT SIWC - инструкция на русском языке

[English README](README.md) | **Русская документация**

Используйте подходящую подписку ChatGPT в собственном Open WebUI через официальный механизм **Sign in with ChatGPT (SIWC)** и **Responses API**. Это независимый проект сообщества, который не связан с OpenAI или Open WebUI и не поддерживается ими официально. Доступность моделей и тарифов определяет OpenAI. Перед развертыванием проверьте [официальный SIWC Quickstart](https://developers.openai.com/siwc/quickstart).

> **Важно:** SIWC не является способом обойти платный API. Адаптер использует официальный OAuth и расходует лимиты подходящего аккаунта ChatGPT. Не используйте одну пользовательскую подписку как общий API для других пользователей.

## 1. Архитектура

```text
Open WebUI
    |
    | Responses API, совместимый с OpenAI
    v
SIWC Adapter
    |
    | Официальный Sign in with ChatGPT
    v
OpenAI
```

Адаптер шифрует учетные данные SIWC, получает список моделей, доступных подключенному аккаунту, и перенаправляет поддерживаемые запросы Responses API. В нем нет отдельного агентного фреймворка, векторной базы, универсального шлюза моделей или собственной базы истории диалогов.

Доступны два способа передачи запросов:

- `RESPONSES_TRANSPORT=http` (по умолчанию): каждый запрос выполняется отдельно через HTTP/SSE.
- `RESPONSES_TRANSPORT=websocket`: адаптер поддерживает авторизованное соединение Responses WebSocket для аккаунта; продолжение беседы происходит с `previous_response_id` и новыми входными элементами. При невозможности продолжения используется HTTP-путь.

## 2. Два независимых входа

**Вход в Open WebUI** предоставляет доступ к вашему собственному сервису чата. Для администрирования общего провайдера может требоваться учетная запись администратора.

**Подключение подписки ChatGPT** - отдельная авторизация на официальной странице OpenAI с согласием на использование соответствующих лимитов. **Ключ OpenAI API для этого не используется.**

## 3. Требования

- Подходящая подписка и аккаунт ChatGPT с доступом SIWC в вашем регионе.
- Актуальный self-hosted Open WebUI с поддержкой провайдера OpenAI-compatible Responses API.
- Docker Compose и частная Docker-сеть, общая для Open WebUI и адаптера.
- Публичный HTTPS-адрес Open WebUI; ответ OAuth поступает на тот компьютер, где открыт браузер.
- Для опубликованного локального companion-приложения - **macOS 13.5 или новее**.
- Сборка companion, если не оговорено иное для конкретного релиза, не подписана и не нотариально заверена Apple. Перед запуском проверьте исходники и контрольную сумму.

## 4. Быстрый запуск в Docker

**Шаг 1.** Настройте частную Docker-сеть, доступную существующему Open WebUI и новому адаптеру. Сначала определите фактическое имя сети в своей инсталляции.

**Шаг 2.** Скопируйте пример конфигурации:

```sh
cp .env.example .env
```

**Шаг 3.** Сгенерируйте ключ доступа к адаптеру, ключ шифрования Fernet и стабильный UUID хоста:

```sh
python -c 'import secrets; print(secrets.token_urlsafe(48))'
python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
python -c 'import uuid; print(uuid.uuid4())'
```

Настройте в `.env`:

| Переменная | Назначение |
| --- | --- |
| `ADAPTER_API_KEY` | Отдельный секрет доступа Open WebUI к адаптеру |
| `SIWC_CREDENTIAL_KEY` | Fernet-ключ шифрования учетных данных |
| `SIWC_HOST_ID` | Уникальный постоянный UUID инсталляции |
| `OPEN_WEBUI_PUBLIC_ORIGIN` | Публичный HTTPS-origin Open WebUI |
| `CONNECT_PUBLIC_URL` | Страница `/siwc/connect` на публичном домене |
| `CONNECT_ADMIN_EMAILS` | Список разрешенных администраторов |
| `OPEN_WEBUI_DOCKER_NETWORK` | Частная Docker-сеть Open WebUI |
| `ADAPTER_INTERNAL_URL` | Внутренний URL адаптера с `/v1` |

**Не изменяйте `SIWC_HOST_ID` после авторизации** - учетные данные привязаны к идентификатору хоста. Храните Fernet-ключ и API-ключ в менеджере секретов, а не в Git.

**Шаг 4.** Настройте существующий аутентифицирующий reverse proxy: запросы `/siwc/*` перенаправляйте в адаптер; защищайте страницы подключения, статуса, конфигурации, проверки, загрузки companion и pairing теми же правилами входа администратора. Прокси обязан удалить переданный клиентом `X-Auth-Request-Email` и добавить этот заголовок заново **только после проверенной аутентификации**. Маршруты `/v1/*` должны оставаться в частной сети.

**Шаг 5.** Запустите сервис:

```sh
docker compose up -d --build
docker compose logs --tail=50 siwc-adapter
```

**Шаг 6.** После входа под разрешенным администратором откройте адрес `https://ваш-домен/siwc/connect`. Не публикуйте API адаптера напрямую в интернет.

Пример Compose создает постоянный Docker volume. Для существующей инсталляции подключите прежний каталог данных к `DATA_DIR`. Резервное копирование должно охватывать и зашифрованные credentials, и Fernet-ключ, причем сам ключ следует защищать отдельно.

**Не изменяйте** `OPENAI_API_BASE_URL=https://api.openai.com/v1` и `OPENAI_AUTH_BASE_URL=https://auth.openai.com`: текущий контракт SIWC не поддерживает произвольный API-прокси.

## 5. Настройка Open WebUI

Добавьте один OpenAI-compatible provider в настройках подключений:

| Параметр | Значение |
| --- | --- |
| Base URL | `http://siwc-adapter:8080/v1` в общей частной сети |
| API key | Значение `ADAPTER_API_KEY` |
| API type | **Responses** |
| Model IDs | Не задавайте вручную; используйте автоматическое обнаружение |

Для WebSocket-режима рекомендуется добавить заголовок:

```json
{"X-OpenWebUI-Chat-Id": "{{CHAT_ID}}"}
```

Это позволяет адаптеру сопоставлять запросы в одном чате. При отсутствии заголовка сопоставление выполняется по доказуемому совпадению истории и ее продолжению. Исходный ID не журналируется и не сохраняется - в памяти используется сокращенный хеш. При необходимости настройте имя через `WS_CONVERSATION_HEADER`.

Откройте `/siwc/connect`, нажмите **«Продолжить с ChatGPT»**, установите локальное приложение для macOS, подтвердите в нем адрес доверенного Open WebUI и завершите авторизацию на официальной странице OpenAI. После этого вернитесь в Open WebUI и выберите обнаруженную модель.

### Если Open WebUI работает на удаленной ВМ

OAuth callback использует адрес `http://127.0.0.1:<port>/auth/callback` на **локальном компьютере с браузером**. Companion на Mac получает callback и защищенно передает результат сопряженному адаптеру на ВМ через HTTPS. Не перенаправляйте callback на ВМ и не вставляйте токены в адрес браузера.

## 6. Совместимость с Responses API

- Модели обнаруживаются через OpenAI и зависят от подключенного аккаунта.
- В upstream SSE отправляется `store: false`; клиентам со streaming передается SSE, прочим - готовый Responses JSON.
- WebSocket-транспорт сохраняет этот внешний контракт и преобразует события сокета в обычные SSE/JSON ответы.
- Поле Open WebUI `reasoning_effort` преобразуется в `reasoning.effort` Responses API.
- Нативные функции Open WebUI передаются модели, а выполнение и подтверждение инструментов остается в Open WebUI.
- Системные сообщения преобразуются в совместимую роль `developer`. Неподдерживаемые SIWC-поля удаляются.

Набор функций SIWC **не равен полному OpenAI API**. Ограничения описаны в [документации OpenAI](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).

### Управление глубиной рассуждений

В Open WebUI **v0.12.0+** используйте встроенные **Model Controls** для выбора `reasoning_effort` отдельно для каждой модели. Настройте доступные модели уровни по официальной документации. Прежний фильтр `integrations/open-webui/functions/siwc_think.py` устарел и предназначен только для Open WebUI **до v0.12.0**. Не включайте его одновременно со встроенными Model Controls. Подробнее: [инструкция интеграции](integrations/open-webui/README.ru.md).

## 7. Кеширование, инструменты и лимиты

SIWC не сохраняет историю на стороне Responses HTTP: обычный HTTP-запрос повторно передает весь `input`. Каждый цикл «модель → инструмент → модель» приводит к новому запросу. Адаптер формирует сериализацию детерминированно для повторного использования одинакового префикса.

- `CACHE_BREAKPOINTS=false` по умолчанию: по проверке автора от **18.10.2026** SIWC resource отвергал `prompt_cache_breakpoint` и `prompt_cache_options` с HTTP 400 `invalid_parameter`. Не включайте без повторной проверки на текущем ресурсе.
- `CACHE_ROUTING_KEY=false` по умолчанию: адаптер может вывести `prompt_cache_key` из начала диалога. Для моделей GPT-5.6+ маршрутизация кеша автоматическая; для более ранних моделей стабильный ключ может быть полезен.
- Уровень reasoning определяется моделью и Open WebUI; адаптер не уменьшает его сам. Каждый входящий запрос порождает ровно один upstream запрос, без скрытого повторного выполнения.

### WebSocket transport

`RESPONSES_TRANSPORT=websocket` поддерживает авторизованное соединение `wss://api.openai.com/v1/responses` и продолжение с `previous_response_id`. Open WebUI продолжает обращаться к адаптеру через обычный HTTP Responses API.

Адаптер ведет в памяти ограниченное состояние отдельных цепочек разговоров: последний ID ответа, хеши элементов и служебные параметры. Он **не хранит** текст диалога, аргументы и результаты инструментов или токены в состоянии цепочек. Полная история остается в Open WebUI.

Продолжение допускается только для точного расширения предыдущего запроса: должны совпадать модель, инструкции, инструменты и предыдущие элементы. Если история изменена, сообщение удалено, соединение утрачено или продолжение отвергнуто, адаптер отправляет **полный контекст**. При проблемах с сокетом применяется ограниченный HTTP fallback; ошибки модели, квоты и политики возвращаются без замены транспорта.

В живых проверках автора на **18.10.2026** SIWC WebSocket принимал продолжение `previous_response_id` в том же соединении, но отвергал `stream_id`. Поэтому адаптер сериализует запросы внутри соединения и использует HTTP при занятой цепочке.

Основные настройки: `RESPONSES_TRANSPORT`, `WS_CONVERSATION_HEADER`, `WS_CONNECTION_MAX_AGE_SECONDS`, `WS_EVENT_TIMEOUT_SECONDS`, `WS_OPEN_TIMEOUT_SECONDS`, `WS_LOCK_TIMEOUT_SECONDS`, `WS_LANE_IDLE_TTL_SECONDS`.

## 8. Телеметрия

`REQUEST_TELEMETRY=true` включает одну структурированную строку JSON в stdout на запрос `/v1/responses`. Просмотр: `docker compose logs siwc-adapter`.

Логируются технические метрики: локальный ID запроса, модель, reasoning, число/размер входных элементов и определений tools, сокращенные SHA-256-отпечатки, совпадения префиксов, тип транспорта, режим продолжения, затраченное время, HTTP-статус, сведения о токенах/кеше и причина fallback. В памяти хранится не более 32 недавних отпечатков.

**Не журналируются:** тексты запросов/ответов, аргументы и результаты инструментов, OAuth credentials и секретные заголовки. Для отключения задайте `REQUEST_TELEMETRY=false`.

## 9. Хранение учетных данных и безопасность

Учетные данные SIWC шифруются Fernet и атомарно записываются в `DATA_DIR/credentials.enc` с правами `0600`. Ключ шифрования задается отдельно через `SIWC_CREDENTIAL_KEY`. Обновление refresh token сохраняется в том же зашифрованном файле. Локальный companion не сохраняет файл с открытыми токенами.

Публичный Open WebUI должен работать через HTTPS. API адаптера должен находиться в частной сети. Все административные `/siwc/*` маршруты защищаются аутентификацией и allowlist администратора. Не доверяйте переданным из браузера identity headers.

См. [Политику безопасности на русском](SECURITY.ru.md).

## 10. Обновление

Перед обновлением ознакомьтесь с release notes. Сохраните `credentials.enc` и Fernet-ключ как связанную пару. Не меняйте `SIWC_HOST_ID`, ключи, `DATA_DIR` и URL провайдера без необходимости. Соберите и разверните проверенную версию, проверьте `/health` и `/v1/models`; сохраните прежний образ для отката. При сохранении исходных credentials и настроек повторная авторизация обычно не требуется.

## 11. Типичные проблемы

| Симптом | Что проверить |
| --- | --- |
| «Требуется вход» на странице подключения | Вход в Open WebUI и доверенный identity header, выставляемый прокси |
| Администратору запрещен доступ | `CONNECT_ADMIN_EMAILS`, правильность email после аутентификации |
| Companion не может связаться с адаптером | Доступный с Mac HTTPS URL; не используйте Docker hostname в `CONNECT_PUBLIC_URL` |
| OAuth callback не завершен | Loopback listener на том же Mac, свежая попытка с `state` и PKCE |
| Нет моделей | Доступность SIWC, связь адаптера с OpenAI, внутренний `/v1` URL и API key |
| Проверка credentials не проходит после переноса | Не изменился ли `SIWC_HOST_ID` |
| Не удается обновить токен | Системное время, доступ к OpenAI, срок действия и отзыв refresh grant |

## 12. Известные ограничения

- Доступность SIWC, лимиты, модели и регионы определяются OpenAI и могут изменяться.
- Адаптер не предоставляет полный набор возможностей OpenAI API.
- Hosted File Search, Code Interpreter, Computer Use и hosted MCP не поддерживаются; нативные функции Open WebUI выполняются самой Open WebUI.
- Background Responses и сохранение истории на стороне API не предоставляются.
- Preview SIWC не включает аудио/видео, Files Upload и Transcription API.
- Опубликованный companion работает только на macOS.
- SIWC не создает и не управляет учетными записями Open WebUI.

## 13. Разработка и тестирование

Требования: Python 3.12+, Node.js 24+, Docker.

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
python -m compileall -q app integrations tests tools
ruff check app integrations tests tools --per-file-ignores "integrations/open-webui/functions/siwc_think.py:I001"
python -m pytest -q
npm --prefix tools ci
node --check tools/authorize.mjs
node --check tools/web_connect.mjs
node --test tools/test_oauth_flow.test.mjs
node tools/test_companion_flow.mjs
docker build -t open-webui-chatgpt-siwc:local .
git diff --check
```

WebSocket-тесты запускаются на искусственном Responses-сервере (`tests/ws_fakes.py`) без подключения к OpenAI. Companion собирается в CI на macOS. Для CI используются только синтетические учетные данные. Реальный вход SIWC требует ручной приемки и **не выполняется** в CI. `tools/ws_acceptance.py` проверяет три фазы в живой среде: простой ответ, продолжение диалога и дополнительный результат инструмента.
