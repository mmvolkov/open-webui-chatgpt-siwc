# Политика безопасности

[English](SECURITY.md) | **Русский**

## Как сообщить об уязвимости

Используйте GitHub **Report a vulnerability** для приватного security advisory, доступного сопровождающим проекта. Не создавайте публичные issue об уязвимости, если исправление еще не выпущено. Опишите затронутую версию, воспроизведение и последствия. Не прикладывайте настоящие токены, персональные данные или реальные идентификаторы аккаунтов.

## Архитектура защиты

- **Хранение учетных данных:** SIWC credentials шифруются Fernet и сохраняются в `DATA_DIR/credentials.enc` атомарно с правами `0600`. Ключ передается отдельно через `SIWC_CREDENTIAL_KEY`, который необходимо хранить и резервировать как секрет.
- **Работа с открытыми токенами:** во время OAuth и передачи токены присутствуют в памяти процессов и внутри защищенных HTTPS-запросов между companion и адаптером. Companion не записывает credentials в открытом виде, адаптер также не сохраняет открытый файл. Не включайте логирование тел запросов и заголовков авторизации в reverse proxy, сервере или трассировке.
- **Защита OAuth:** companion использует PKCE S256, криптографически случайный `state` и `nonce` от сопряженного адаптера. Подпись ID token проверяется по JWKS OpenAI, дополнительно проверяются issuer, audience, срок действия, subject и nonce до handoff. Адаптер повторяет проверку до сохранения credentials.
- **Callback и сопряжение:** OAuth callback работает на loopback локального Mac. Для Open WebUI на удаленной ВМ короткоживущий pairing challenge связывает браузер и companion. Companion передает результат адаптеру по HTTPS. Токены и pairing grants не помещаются в URL. Код авторизации приходит в query OAuth callback и сразу обрабатывается. Браузер использует фрагмент URL для локального handoff и удаляет его перед передачей данных.
- **Хранение в браузере:** access token, refresh token и API key адаптера не сохраняются в localStorage.
- **Сеть:** используйте HTTPS для всех публичных адресов Open WebUI и операций handoff. HTTP допустим только для локального loopback. Не открывайте API `/v1` для недоверенной сети.
- **Авторизация адаптера:** `/v1/*` требует отдельный Bearer API key. Административные `/siwc/*` endpoints требуют доверенного заголовка идентификации и разрешенной учетной записи администратора. Прокси должен удалять клиентские копии заголовка и добавлять его только после аутентификации Open WebUI.
- **Размещение:** адаптер и Open WebUI должны находиться в общей частной сети. Через reverse proxy публикуется только защищенная страница подключения. API key и Fernet key хранятся в менеджере секретов.
- **Обновление токенов:** rotated refresh token атомарно записывается в зашифрованное хранилище. Ошибки не включают значения токенов или тела ответов провайдера.

## Границы тестирования

CI и тесты используют синтетические учетные данные. Реальная авторизация аккаунта проверяется вручную и не входит в CI. Не добавляйте реальные credentials, приватные адреса, записи входа или продуктивные журналы в issues и PR.

Использование SIWC регулируется [условиями OpenAI](https://openai.com/policies/sign-in-with-chatgpt-terms/).
